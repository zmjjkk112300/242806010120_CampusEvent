## 12.2 功能变化一览

| 能力 | baseline-v1 | change-v2 |
|---|---|---|
| 报名方式 | 直接报名、管理员审核 | 再加「年级限定直接报名」 |
| 学生年级 | 无此概念 | `grade` 1—4，界面显示「大三」等中文 |
| 报名校验 | 时间 / 重复 / 名额 | 上述三条 + 年级区间（仅策略内生效） |
| 通知渠道 | 站内消息 | 站内消息 + 模拟邮件（并列观察者） |

| 演示活动 | 4 个 | 5 个：新增「学科竞赛集训营（大二大三专属）」 |

## 12.3 部署与验证

```bash
# 服务器（/opt/campus-event）
git pull            # 或解包上传后覆盖
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q          # 期望 36 passed
sudo systemctl restart campus-event
journalctl -u campus-event -n 30       # 应看到「v2 结构迁移已执行」
```

要点：旧库无需重建，`ensure_schema()` 在应用启动时补列；`email_records` 表由 `create_all` 新建；既有活动 `min_grade/max_grade` 为 NULL，等价于“无年级限制”，历史行为不变。

演示故障邮件：

```bash
CAMPUS_EVENT_EMAIL_FAIL_TIMES=1 sudo systemctl restart campus-event   # 首封邮件必定失败
# 观察：报名成功页正常，/admin/emails 出现「发送失败」与错误原因
```

## 12.4 回滚方案

| 场景 | 操作 | 影响 |
|---|---|---|
| 仅逻辑回退（代码） | `git checkout baseline-v1`（或 `git revert` 变更提交），重启服务 | 前端不再有年级/邮件入口；数据库新增列与表保留但不再使用，**无需删表**，不影响旧功能 |
| 部署回退 | 服务器上 `git checkout baseline-v1 && systemctl restart campus-event` | 学生端恢复原流程；`email_records` 残留数据无害 |
| 彻底回退（含数据） | 用部署前备份 `instance/campus_event.db` 覆盖后重启 | 恢复变更前全部数据；建议变更前执行 `cp instance/campus_event.db instance/campus_event.db.bak` |

回滚安全性依据：新列全部可空或有默认值，新表无人引用，`RegistrationService` 与 `test_acceptance.py` 未改动，故基线代码可在 v2 数据库上直接运行。

## 12.5 已知限制（v2 仍存在）

1. 邮件为模拟实现，不外发真实邮件；真实 SMTP 只需替换 `EmailSender` 实现，观察者与表结构无需改动。
2. 邮件发送为同步阻塞，量级变大需改为任务队列；当前课程场景可接受。
3. 年级限定仅支持连续区间（`min_grade`—`max_grade`），不支持“仅大一和大三”这类离散组合。
4. 邮件失败不自动重试，只留记录与日志；重复投递依赖 `event_key` 幂等。
